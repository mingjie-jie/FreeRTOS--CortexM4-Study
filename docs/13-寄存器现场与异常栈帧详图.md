# 13｜画全了：硬件栈帧 + 软件栈帧 + TCB + PSP + PC

> **核心解惑**：保存时 R4 存到哪儿？为什么 Task1 原 R2 不需要 PendSV 保存？读取 PC 时为什么固定是基本栈帧 `+0x18`？LDMIA 之后 PSP 指向哪儿？

## 1. 一次没有使用 FPU 扩展现场的 Task1 → Task2 切换

假设 Task1 在 Thread Mode 使用 PSP，异常发生之前：

```text
Task1 PSP（异常前） = 0x20001000
Task1 原 R2        = 0x12345678
Task1 原 PC        = 0x08003456  （示意）
Task1 原 R4        = 0x0000000B
Task1 原 R5        = 0x0000001F
```

### 第一阶段：CPU 自动入栈 8 个字（32 字节）

Cortex-M4 硬件将基本异常栈帧存到 `0x20000FE0 ～ 0x20000FFF`；PSP 自动变成 `0x20000FE0`：

| RAM 地址 | 内容 | 谁保存的？ |
|---|---|---|
| `0x20000FE0` | **任务原 R0** | 硬件 |
| `0x20000FE4` | 任务原 R1 | 硬件 |
| `0x20000FE8` | **任务原 R2 = 0x12345678** | 硬件 |
| `0x20000FEC` | 任务原 R3 | 硬件 |
| `0x20000FF0` | 任务原 R12 | 硬件 |
| `0x20000FF4` | 任务原 LR | 硬件 |
| `0x20000FF8` | **恢复 PC = 0x08003456** | 硬件 |
| `0x20000FFC` | xPSR | 硬件 |

注意 **Handler 此时的 R2 并不一定等于表里的 0x12345678**；它马上会被 `LDR R2,[R3]` 用来放旧任务 TCB 地址。

### 第二阶段：PendSV 软件保存 9 个字（36 字节）

```asm
MRS   R0,PSP
STMDB R0!,{R4-R11,R14}
```

原 R0=`0x20000FE0`；新 R0=`0x20000FE0-0x24=0x20000FBC`。

| RAM 地址 | 内容 |
|---|---|
| `0x20000FBC` | R4（11） |
| `0x20000FC0` | R5（31） |
| `0x20000FC4` | R6 |
| `0x20000FC8` | R7 |
| `0x20000FCC` | R8 |
| `0x20000FD0` | R9 |
| `0x20000FD4` | R10 |
| `0x20000FD8` | R11 |
| `0x20000FDC` | **R14 = 该任务的 EXC_RETURN**（例如 `0xFFFFFFFD`） |
| `0x20000FE0` | 旧任务 R0（基本硬件帧开始） |
| `0x20000FE8` | 旧任务 R2（硬件已保存） |
| `0x20000FF8` | 旧任务 PC（硬件已保存） |
| `0x20000FFC` | 旧任务 xPSR |

这张表里有两个 LR：

- `[0x20000FDC]`：Handler 中 R14 的 **EXC_RETURN**，软件存的。
- `[0x20000FF4]`：Task1 本来运行时的 **函数 LR**，硬件存的。

**它们意义不同、地址不同，都是必要现场。**

### 第三阶段：TCB 记住“保存后栈顶”

```asm
LDR R3, =pxCurrentTCB   ; R3 = &pxCurrentTCB
LDR R2, [R3]            ; R2 = &Task1_TCB
STR R0, [R2]            ; Task1_TCB.pxTopOfStack = 0x20000FBC
```

任务真正的局部栈变量还留在 Task1 原有的更高地址栈区。TCB 无须存放所有局部变量，也**不直接储存 PC 值**；它只需记住这张现场布局从哪里开始。

## 2. 图解：地址方向不能搞反

```text
           高地址 ↑
   ┌──────────────────────────────┐
   │ Task1 原先的函数栈帧、局部变量 │
   ├──────────────────────────────┤ 0x20001000：异常前 PSP
   │ xPSR                         │ 0x20000FFC
   │ Task1 PC                     │ 0x20000FF8
   │ Task1 原 LR                  │ 0x20000FF4
   │ Task1 R12 / R3 / R2 / R1 / R0│ ... 至 0x20000FE0
   ├──────────────────────────────┤ 0x20000FE0：硬件入栈后 PSP
   │ EXC_RETURN（软件保存 R14）    │ 0x20000FDC
   │ R11 / R10 / ... / R4         │ ... 至 0x20000FBC
   └──────────────────────────────┘ 0x20000FBC：TCB.pxTopOfStack
           低地址 ↓
```

从低地址往高地址“按寄存器编号升序存储”的表格在第 1 节；这张图从上到下画低地址，容易与常见“栈向下增长”图联系起来。

## 3. 恢复 Task2 时地址怎样变化？

假设选到 Task2 后，其 `TCB2.pxTopOfStack = 0x20001FBC`，同样为无浮点扩展的现场。

```asm
LDR   R1,[R3]               ; R1 = &Task2_TCB
LDR   R0,[R1]               ; R0 = 0x20001FBC
LDMIA R0!,{R4-R11,R14}     ; R0 += 0x24 → 0x20001FE0
MSR   PSP,R0               ; PSP = 0x20001FE0（Task2 硬件基本帧）
BX    R14                  ; 异常返回：硬件自动恢复 Task2 R0..xPSR
```

Cortex-M4 异常返回按 EXC_RETURN 的编码，从 PSP 所指向的硬件帧中读出 PC，并让任务继续运行；**不是 LDMIA 在手动恢复 PC**。基本栈帧中 PC 槽相对于基本栈帧起始地址偏移 `+0x18`。

## 4. 把 R2 的困惑完全说清楚

| 时刻 | 物理寄存器 R2 正在保存什么？ | Task1 原 R2 的安全位置 |
|---|---|---|
| Task1 未被中断 | Task1 当前计算数据 | R2 寄存器本身 |
| PendSV 异常已进入 | 仍可能被 Handler 后续覆盖 | **Task1 PSP 基本帧 + 0x08** |
| `LDR R2,[R3]` 后 | **Task1_TCB 地址**（临时工作值） | 仍在 Task1 栈里 |
| `STR R0,[R2]` 后 | R2 的临时任务完成 | 仍在 Task1 栈里 |
| `BL vTaskSwitchContext` 后 | R2 可以任意变化 | 仍在 Task1 栈里 |
| Task1 再次被调度并异常返回 | 自动恢复为 Task1 原 R2 | 已回到 R2 寄存器 |

**问：既然 Handler 的 R2 没保存，恢复怎么找 Task1 的 TCB？**

答：调度器在内核任务列表中一直持有 TCB 对象及其地址；切回时重新把 `pxCurrentTCB` 指向 Task1_TCB，再通过它的首成员找到 `pxTopOfStack`。完全无需找回旧的 Handler R2。

## 5. FPU 扩展现场：为什么不能对所有任务都套用 +0x18？

对普通基本栈帧 `PC = *(uint32_t *)(PSP + 0x18)` 在教学中成立。但若发生异常时浮点状态有效（EXC_RETURN.bit4 为 0），硬件预留/保存的扩展异常帧还包含 S0～S15、FPSCR 及预留槽；PendSV 另外按需存 S16～S31，栈顶布局变长。

因此 **判断 EXC_RETURN 的栈帧类型后，才能确定基本帧的起始位置**。在含 FPU 扩展帧的情形，通常扩展浮点区位于基本帧的低地址一侧；不要直接把扩展帧 PSP 当作基本帧的 R0 起点。

> 本章的整套具体地址演算均明确假设：没有浮点扩展帧、异常前栈已满足要求的对齐、没有额外栈对齐填充。真实程序还必须遵循 CCR.STKALIGN/xPSR[9] 等规则。

## 6. 最后一分钟复习

- `MRS R0,PSP`：R0 指向旧任务硬件异常帧。
- `STMDB R0!,{R4-R11,R14}`：R0 减 36 字节，保存软件现场。
- `STR R0,[R2]`：旧任务 TCB 记录保存后的最低地址。
- `BL vTaskSwitchContext`：决定下个 TCB（可能仍是自己）。
- `LDMIA R0!,{R4-R11,R14}`：从新任务栈读回软件现场，R0 加 36 字节。
- `MSR PSP,R0`：新任务 PSP 指向其硬件异常帧。
- `BX R14`：根据 EXC_RETURN，硬件恢复 PC。
