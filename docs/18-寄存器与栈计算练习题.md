# 18｜自测题：寄存器、STMDB/LDMIA、指针与任务切换（含答案）

> 建议先做题，再展开答案；所有地址均为教学假设，涉及 FPU 时会另有提示。

## A. 寄存器基础

**1.** R0～R3 与 R4～R11 在 AAPCS 中的调用约定有何不同？这和 PendSV 保存 R4～R11 的原因是否完全相同？

**2.** `BL Function_B` 如何改变 PC 与 LR？如果 Function_B 又执行 `BL Function_C`，原来函数返回地址怎么办？

**3.** 为什么 `BX R14` 在普通 C 函数中可能是普通返回，在 SVC/PendSV 中却能恢复整个任务的 PC？

**4.** PendSV 中看到 R2 保存 `0x20000100`（旧 TCB），是否意味着 Task1 原来的 R2 也变成 `0x20000100`？

## B. 内存地址计算

**5.** `R0=0x20001000`，执行 `STMDB R0!,{R4-R11,R14}`，写完后 R0 等于多少？R4 和 R14 分别位于什么地址？

**6.** 紧接第 5 题，重新令 `R0=0x20000FDC`，执行 `LDMIA R0!,{R4-R11,R14}`，读取了多少字节，R0 新值是多少？

**7.** 任务异常之前 `PSP=0x20001000`，没有 FPU 扩展帧和额外对齐，Cortex-M 基本异常入栈后 PSP 是多少？PC、R2 的保存槽分别是什么地址？

**8.** 接第 7 题，PendSV 再保存 9 个软件寄存器，最终写入旧 TCB 的 `pxTopOfStack` 地址是多少？

## C. 二级指针与 TCB

**9.** 假设：

```text
&pxCurrentTCB = 0x20000020
[0x20000020] = 0x20000100
[0x20000100] = 0x20000FBC
```

执行三条汇编后 R3/R2/R0 是多少？

```asm
LDR R3,=pxCurrentTCB
LDR R2,[R3]
LDR R0,[R2]
```

**10.** 运行 `vTaskSwitchContext()` 后 `[0x20000020]=0x20000200`，R3 仍是 `0x20000020`。为什么可以 `LDR R1,[R3]` 得到新 TCB？

## D. 异常与任务延时

**11.** 对基本栈帧，为什么 PC 位于 `PSP+0x18`？在浮点扩展帧中能否不加判断直接按这个偏移读 PC？

**12.** `osDelay(1000)` 到期后，CPU 是直接跳转到应用里的下一行 C 代码吗？

**13.** 为什么所有用户任务都 BLOCKED 的情况下，Mini RTOS 还要有 IdleTask？

**14.** `STMDB SP!,{R0,R3}` 是存到 Task1 的 PSP 栈还是 MSP 栈？为什么？

**15.** `MSR CONTROL,R0` 把 R0=0 写入 CONTROL 等于“关闭 FPU”吗？

<details>
<summary><strong>参考答案（做完再展开）</strong></summary>

1. R0～R3 通常允许被调用函数改写，R4～R11 通常须保留（R9 平台相关）。PendSV 保存 R4～R11 的直接原因是硬件基本异常帧没有保存它们，不是因为“所有局部变量都在这些寄存器”。
2. `BL` 设置 LR 为返回位置、PC 转函数入口；函数嵌套时被调用者/调用者按 ABI 保存返回链路，常使用栈保存 LR。
3. Handler LR 是 EXC_RETURN 编码，硬件识别后执行异常返回，包括自动从指定 PSP/MSP 栈恢复 PC 等；普通函数 LR 通常是代码返回地址。
4. 不是。Task1 原 R2 已经由硬件异常入栈；Handler 现在可以用 R2 临时存 TCB 地址。
5. `0x20000FDC`；R4 位于 `0x20000FDC`，R14 位于 `0x20000FFC`。
6. 9×4=36 字节；R0 更新为 `0x20001000`。
7. PSP=`0x20000FE0`；PC 槽 `0x20000FF8`，R2 槽 `0x20000FE8`。
8. `0x20000FBC`（`0x20000FE0-0x24`）。
9. R3=`0x20000020`，R2=`0x20000100`，R0=`0x20000FBC`。
10. R3 保存的是**全局变量所在的 RAM 地址**，调度器改变 RAM 中该变量的值，因此重新解引用即可得到新 TCB。
11. Cortex-M 基本异常帧的固定格式：R0/R1/R2/R3/R12/LR/PC/xPSR，PC 是第 7 个字，偏移 6×4=`0x18`；扩展帧不能直接套。
12. 一般是恢复 `vTaskDelay` 或其调用路径被中断的机器指令，完成函数返回，最终回到应用下一行。
13. Idle 始终 READY，在所有用户任务 BLOCKED 时仍有可运行任务；还能承担空闲处理/低功耗等待。
14. **MSP**，因为进入 PendSV 后处于 Handler Mode；不是旧任务 PSP 栈。这样可临时保护 Handler 自己的 R0/R3，保持 C 函数调用栈对齐。
15. 不是；它清 CONTROL.FPCA、设置 Thread 的特权/栈选择状态，并非把芯片 FPU 单元永久关闭。

</details>
