# 07｜`STMDB` / `LDMIA` 的地址到底怎么走？

> **新增大例题**：[13-硬件 32B + 软件 36B 的完整内存表](13-寄存器现场与异常栈帧详图.md)、[18-计算练习题](18-寄存器与栈计算练习题.md)。

原代码：

```asm
MRS   R0, PSP
STMDB R0!, {R4-R11, R14}
...
LDMIA R0!, {R4-R11, R14}
MSR   PSP, R0
```

`STMDB` = Store Multiple, Decrement Before，`LDMIA` = Load Multiple, Increment After。`!` 表示指令完成后将更新后的地址回写到基址寄存器。

假设**进入 STMDB 前**：

```text
R0 = 0x20001000
寄存器个数 = 8 + 1 = 9
字节数 = 9×4 = 36 = 0x24
```

## 1. STMDB 实际映射

新 R0 为：

`0x20001000 - 0x24 = 0x20000FDC`

| 内存地址 | 存储寄存器 |
|---|---|
| `0x20000FDC` | R4 |
| `0x20000FE0` | R5 |
| `0x20000FE4` | R6 |
| `0x20000FE8` | R7 |
| `0x20000FEC` | R8 |
| `0x20000FF0` | R9 |
| `0x20000FF4` | R10 |
| `0x20000FF8` | R11 |
| `0x20000FFC` | R14（此时 EXC_RETURN） |

**重要修正**：概念上可以理解为“预留更低地址的 36 字节，然后从低地址按寄存器编号递增放入”。不要想成 R4 从 `0x20000FFC` 一格格往下挤。最低编号寄存器 R4 放在这组存储的最低地址。

## 2. LDMIA 实际映射

恢复时令 R0 = `0x20000FDC`：

- `[R0]`（`0x20000FDC`）恢复给 R4。
- `[R0+4]` 恢复给 R5……
- `[R0+0x20]`（`0x20000FFC`）恢复给 R14。
- R0 更新为 `0x20001000`。

**LDMIA 不需要“先往下找”**；任务 TCB 中已经保存了当前最低地址 `0x20000FDC`。恢复时从这里开始向高地址读取。

## 3. 什么时候变回 PSP？

保存阶段：`MRS R0, PSP` → `STMDB R0!` → `STR R0,[R2]`，没有直接修改 PSP。

恢复阶段：`LDR R0,[R1]` → `LDMIA R0!` → `MSR PSP,R0`。这时候 PSP 指向新任务剩余的**硬件异常栈帧**，再由 `BX EXC_RETURN` 让 CPU 完成硬件出栈。

## 4. FPU 下地址还会怎样变化？

若 `EXC_RETURN.bit4 == 0`：软件还会为 S16～S31 保存 **16×4 = 64 字节**。这部分栈区位于 R4-R11/R14 保存区域的高地址侧（因为 VSTMDB 先执行、STMDB 后执行）；硬件异常帧又在更高地址处。还要考虑 FPU 硬件扩展帧与可能的对齐填充，不能把所有任务栈一律认定为只有 36+32 字节。
