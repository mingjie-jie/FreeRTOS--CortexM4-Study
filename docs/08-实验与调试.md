# 08｜三个实验：从纯 C 到观察真实寄存器

## 实验 A：两个纯 C 周期性任务

进入 `examples/pure_c_scheduler`，编译并运行 `main.c`：

```bash
cc -std=c11 -Wall -Wextra -pedantic main.c -o scheduler_demo
./scheduler_demo
```

本示例使用**虚拟毫秒计数**，不依赖 HAL，也不会占用 MCU 定时器。它只是轮询调用两个短小任务的回调，具有基本 TCB/优先级/时间条件：**不具备抢占式上下文切换，也没有独立的任务 PSP**。故意这样设计，是为了把“调度算法”和“底层现场切换”拆开理解。

观察：Task1 每 500ms 被调一次，Task2 每 1000ms 被调一次。同一时刻到期时优先级较高者先运行。两任务函数均必须返回，否则调度器无法继续调用下一个回调。

## 实验 B：纯 C 模拟栈帧保存与恢复

进入 `examples/context_simulation`，编译 `main.c`：

```bash
cc -std=c11 -Wall -Wextra -pedantic main.c -o context_demo
./context_demo
```

步骤：

1. 初始化 Task1 与 Task2 的“寄存器镜像”。
2. 将两份寄存器镜像保存在各自任务的栈数组中。
3. 从 Task1 的栈恢复寄存器，模拟执行指令（改动 R4、R5）。
4. 保存 Task1，然后从 Task2 的栈恢复寄存器，改动 Task2 的寄存器。
5. 再切回 Task1，检查 R4/R5 回到它自己的数值。

这是对 `STMDB` / `LDMIA` 内存效果的**模拟**，不是 ARM CPU 真正的异常上下文切换。可修改数组初始值、切换顺序观察。

## 实验 C：在 STM32F407 上查看汇编和寄存器

将 `examples/stm32_register_lab/task_register_lab.c` 放入已有 Keil/CubeIDE STM32 工程，确保工程已配置启动代码与芯片相关库（这个文件**不是独立 STM32 工程**）。从 `main()` 某个初始化后的位置调用 `RegisterLab_Run()`，或在 Debug 状态下直接单步跟进函数。

**调试建议：**

1. 先用低优化等级（例如 `-O0`），避免函数被内联或变量全部常量折叠；代码采用 `volatile` 防止关键计算消失。
2. 打开 Disassembly、Registers、Memory、Call Stack。
3. 在 `RegisterLab_Add` 前后观察 `BL/BLX`、LR、R0、R1、R0 返回值。
4. 单步进 `RegisterLab_Nested`，观察为什么调用另一个函数时 LR 可能需要保存。
5. 比较 `-O0` / `-O2` 下的指令与栈使用。优化结果未必一致。
6. 若已有 FreeRTOS 工程，可在 `xPortPendSVHandler` 入口设断点，观察 `PSP`、`pxCurrentTCB`、`pxTopOfStack` 与异常栈帧。

**断点观察建议**：

| 位置 | 观察对象 | 你应该发现什么 |
|---|---|---|
| `MRS R0, PSP` 之后 | R0、PSP | 二者数值相等 |
| `STMDB R0!, {R4-R11,R14}` 之后 | R0、PSP | R0 减少 36 字节，PSP 尚未通过本指令改变 |
| `STR R0,[R2]` 之后 | R2、Memory | TCB 首字保存新的 R0 |
| `BL vTaskSwitchContext` 前后 | pxCurrentTCB | 可能指向另一任务；也可能不变 |
| `LDR R1,[R3]` 之后 | R1 | 最新被选中的 TCB 地址 |
| `MSR PSP,R0` 之后 | PSP | 指向即将恢复的任务异常栈帧 |
| `BX R14` 之后 | PC | 已返回任务代码位置 |

**重要**：任务/异常栈调试时，单步行为可能受到 FPU lazy stacking、优化、断点和调试器异常处理影响，需结合反汇编和寄存器视图判断。不要把教学版伪代码替换生产工程中的完整 port 实现。

## 常见踩坑

- STM32 HAL 使用 SysTick 作时间基准，与 FreeRTOS SysTick Handler 冲突：需要合理迁移/统一 tick 实现，不能简单定义两个 `SysTick_Handler`。
- ARMCC5 `__asm void` 不能直接用 GCC 编译；GCC 常用 `naked` + `__asm volatile`。
- 在普通 C 函数随意设置 PSP/改 LR 后 `BX`，可能破坏函数序言/栈帧，引发 HardFault。
- 把 `EXC_RETURN` 当普通函数地址，或把异常里 Handler 的 LR 与任务旧 LR 混为一谈。
- 使用 FPU 却忽略浮点上下文保存；或未维护 8 字节栈对齐。
- 用 `HAL_Delay` 当作任务让出 CPU：HAL 裸机默认实现是计数等待，并非 RTOS 阻塞调度。
