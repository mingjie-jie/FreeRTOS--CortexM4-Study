# 06｜第一次启动任务：prvStartFirstTask、SVC、人工栈帧

> **新增扩展阅读**：[17-SVC Handler 逐条汇编](17-SVC与PendSV完整汇编寄存器跟踪.md)、[14-CONTROL/VTOR/BASEPRI](14-CortexM特殊寄存器与中断屏蔽.md)。

## 1. 任务第一次运行，没有“上次 PC”，怎么办？

任务创建时，由 `pxPortInitialiseStack()` 在任务的独立栈里构造一个**模拟异常返回所需的初始栈帧**。典型内容：

```text
低地址 → [R4..R11 预留][EXC_RETURN=0xFFFFFFFD]
          [R0=任务参数][R1][R2][R3][R12][LR=任务错误退出入口]
          [PC=任务函数入口][xPSR=0x01000000] ← 高地址
```

具体排列方向及可选填充由移植代码决定。`xPSR=0x01000000` 表示 Thumb 状态位。任务函数入口地址是由创建任务时提供的函数指针写入栈帧的，不是第一次运行时重新扫描 C 源码找到的。

## 2. 启动调用链

```text
main
  └── vTaskStartScheduler()   [tasks.c]
        └── xPortStartScheduler() [port.c]
              └── prvStartFirstTask() [port.c 的 ARMCC/RVDS 汇编]
                    └── SVC 0
                          └── vPortSVCHandler() [按向量表进入]
                                └── BX EXC_RETURN → Task1() 开始
```

## 3. `prvStartFirstTask` 逐条解读

```asm
PRESERVE8
LDR R0, =0xE000ED08  ; SCB->VTOR 寄存器地址
LDR R0, [R0]         ; 当前向量表基地址
LDR R0, [R0]         ; 向量表第一个字 = 初始 MSP
MSR MSP, R0          ; 恢复初始 MSP，抛弃启动阶段的普通调用栈

MOV R0, #0
MSR CONTROL, R0      ; 清除 FPCA，设 Thread 特权/MSP 选择
CPSIE I              ; 清除 PRIMASK
CPSIE F              ; 清除 FAULTMASK（F 不是 FPU！）
DSB
ISB
SVC 0                ; 触发系统服务异常
NOP
NOP
```

`0xE000ED08` 严格说是 **SCB 的 VTOR**（原源码注释写“NVIC offset register”是历史称法，不够准确）。如果 APP 经 Bootloader 重定位了向量表，读取的是**当前 VTOR** 而非假设一定在 `0x08000000`。

为什么恢复 MSP？启动前 C 函数调用可能已经使用了 MSP，首次调度准备转由任务使用 PSP；异常栈需要干净、有效的 MSP。

`MSR CONTROL,0` 清除 FPCA，可避免 SVC 启动时因为先前浮点活动导致不必要的 FPU 延迟压栈预留；不是关闭 FPU。`PRESERVE8` 为汇编器栈对齐约定声明。

## 4. 谁真正“决定 Task1 的 PC”？

不是 `SVC 0` 跳到 Task1，而是 SVC Handler 中：

```asm
LDR R3, =pxCurrentTCB
LDR R1, [R3]
LDR R0, [R1]
LDMIA R0!, {R4-R11,R14}  ; R14 得到 EXC_RETURN
MSR PSP, R0             ; PSP 指向人工硬件异常帧
ISB
MOV R0, #0
MSR BASEPRI, R0
BX R14                  ; 硬件从 PSP 读取 PC/其他寄存器
```

最后，PC 变为**初始栈帧中预先写入的任务入口地址**，第一个任务才正式开始执行。这个路径只用于首次启动；以后任务切换使用 PendSV。

## 5. SVC 与 PendSV 根本区别

- SVC Handler：只需**恢复**选中的第一个任务的初始现场，不需要保存一个已在 RTOS 中运行的旧任务。
- PendSV Handler：先保存当前任务、调用调度器、再恢复下一个任务。
- SysTick Handler：更新时间和调度时机，并不是直接手动替换任务 PC。
