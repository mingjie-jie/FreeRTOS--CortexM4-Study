# 01｜CPU 如何执行 C 代码：PC、BL、BX、函数指针

## 1. 先回答最初的问题

**CPU 不会“从上往下执行 C 代码”。** 编译器先把 C 代码翻译为机器指令；在顺序执行情况下，CPU 按指令长度推进取指位置。Cortex-M4 使用 Thumb / Thumb-2，指令可能长 16 或 32 bit；并非每条指令都 `PC += 4`。流水线与“读 PC 的值”存在架构定义的差异，因此调试时通常说 PC 代表代码执行位置，而不把它机械地等同于当前指令地址。

```c
int add(int a, int b) { return a + b; }
int main(void) { int x = add(10, 20); for (;;) {} }
```

可能对应以下**教学示意**（实际优化器可内联、常量折叠）：

```asm
MOVS R0, #10       ; 第 1 个整数参数
MOVS R1, #20       ; 第 2 个整数参数
BL   add           ; LR <- 返回位置；跳到 add
; 这里获得 R0 返回值

add:
ADDS R0, R0, R1   ; R0 <- 30
BX   LR           ; 返回调用点之后
```

## 2. 四种控制流需要区分

| 指令/事件 | 对程序做了什么 | 是否属于任务切换 |
|---|---|---|
| `B label` | 无条件分支；不自动保存返回位置 | 否 |
| `BL label` | 函数调用：保存返回地址到 LR，跳转 | 否 |
| `BX LR` | 普通执行流中根据 LR 返回 | 否 |
| `BLX Rn` | 经寄存器中的函数指针调用，更新 LR | 否 |
| 异常进入 / `BX EXC_RETURN` | 硬件保存 / 恢复异常栈帧 | 可能是 RTOS 切换的一部分 |

**最重要的区别**：普通函数调用沿着当前调用栈执行并返回；FreeRTOS 调度需要在不同任务的栈与寄存器现场间切换。

## 3. 为什么嵌套函数调用要保护 LR？

```c
void C(void) { /* ... */ }
void B(void) { C(); }
void A(void) { B(); }
```

执行 `BL B` 会覆盖 LR，而 A 还需要回到调用 A 的地方，因此编译器通常会在适当时机将 LR 保存到栈，并在返回时恢复。常见形式：

```asm
PUSH {R4, LR}
BL   B
POP  {R4, PC}     ; 弹出保存的返回位置到 PC
```

不是**每个函数**都必须入栈 LR：无后续嵌套调用的叶函数可直接使用 `BX LR`；尾调用或内联会改变表面形式。

## 4. 函数参数和调用约定

AAPCS 常见整数/指针参数依次使用 R0、R1、R2、R3，常见 32-bit 整数返回值在 R0；更多参数及复杂类型遵循更详细的规则。R0～R3、R12 是调用者保存寄存器；R4～R8、R10、R11 是被调用者保存寄存器；R9 具有平台约定的特殊性；SP、LR、PC 有独立职责。

例如：

```c
void Task1(void);
void (*fn)(void) = Task1;
fn();          // 调用，可能通过 BLX 寄存器
```

`fn = Task1` 只是保存地址；`fn()` 才发生调用。`PC = &task1();` 不是合法的 C 语言写法，且即使能更改执行地址，也**不等于上下文切换**。

## 5. 为什么 while(1) 任务不能靠函数返回进行轮换？

```c
void task1(void) { while (1) { /* ... */ } }
void task2(void) { while (1) { /* ... */ } }
int main(void) { task1(); task2(); } // task2() 永远不会因顺序调用而到达
```

普通调用需要被调用函数返回；FreeRTOS 则让每个任务有独立栈、挂起与恢复位置。

## 6. 裸机程序上电从哪里开始？

复位时，Cortex-M 从向量表获取初始 MSP（首字）与 Reset_Handler（第二字），而不是直接运行 `main()`。进入 Reset_Handler 后经历运行库初始化，再调用 main。Bootloader 跳 APP 也需要处理目标映像的 MSP、入口、向量表和运行状态。
