## 核心 Q&A

**Q1：裸机代码为什么看起来从上往下运行？**  
A：C 被编译为机器指令；CPU 按 PC 指示执行，默认顺序取指，遇到分支/调用/异常时改变控制流。

**Q2：函数调用和任务切换的区别？**  
A：`BL` 调用函数、更新 LR，通常沿用当前调用栈；任务切换要恢复目标任务的完整执行现场和独立任务栈。

**Q3：直接写 `PC = &task1()` 可以切换任务吗？**  
A：该表达式本身不是合法 C；只改 PC 无法恢复另一任务的 PSP、寄存器与异常栈帧。

**Q4：TCB、PSP、PC 分别干什么？**  
A：TCB 是软件任务档案；PSP 是任务栈地址寄存器；PC 是代码执行位置。

**Q5：每个任务都有一个硬件 PSP 吗？**  
A：没有。CPU 只有一套 PSP；任务栈分别驻留 RAM，TCB 的 `pxTopOfStack` 记住切出后的栈顶。

**Q6：为什么 R4～R11 不够放所有局部变量？**  
A：编译器可用其他寄存器、栈槽、复用寄存器、优化消除等；任务不限制为 8 个变量。

**Q7：FreeRTOS 如何知道哪个变量在哪个寄存器？**  
A：它不需要知道变量名；按寄存器编号与内存位置保存现场，编译器生成的指令保持一致。

**Q8：`STMDB` 是从 PSP 往下逐个存吗？**  
A：读取 PSP 到 R0 后，`STMDB R0!` 在低地址开出空间，按寄存器号升序映射到低→高地址；只更新 R0，不直接更新 PSP。

**Q9：`LDMIA` 要先往下找地址再往上读吗？**  
A：不用。TCB 已经保存**新低地址**，`LDMIA R0!` 从这里向高地址读并更新 R0。

**Q10：R2 为什么任务切换后不使用/保存？**  
A：Handler 中的 R2 是旧 TCB 地址，`STR R0,[R2]` 后任务完成；任务原 R2 已由硬件异常栈帧保存。

**Q11：为什么保留 R3？**  
A：R3 保存 `pxCurrentTCB` 全局变量自身的地址；调度器改变它的**值**而不改变它的**存放位置**，所以新任务 TCB 可通过 R3 再次读取。

**Q12：为什么调度器调用前 `STMDB SP!,{R0,R3}`？**  
A：保护 Handler 的临时寄存器并确保调用 C 函数时 8 字节栈对齐；Handler SP 是 MSP。

**Q13：为什么 `BX R14` 能恢复 Task2 的 PC？**  
A：R14 装的是 Task2 保存的 EXC_RETURN，CPU 依它从 Task2 的 PSP 异常栈帧恢复 PC 等。

**Q14：SVC / PendSV / SysTick 各干什么？**  
A：SVC 启动第一个任务，PendSV 完成后续上下文切换，SysTick 更新时间并在需要时请求调度。

**Q15：`prvStartFirstTask()` 为什么重置 MSP？**  
A：放弃调度启动之前的普通调用栈，为异常处理恢复初始主栈位置；然后通过 SVC 进入第一个任务。

**Q16：可以 100% 标准 C 实现 STM32 抢占式上下文切换吗？**  
A：可以纯 C 编写协作式任务调度/状态机；真正恢复任意时刻的 CPU 寄存器和异常返回，常规 Cortex-M 实现需要处理器相关的汇编或编译器特性。

## 速查表

| 语句 | 速记 |
|---|---|
| `MRS R0, PSP` | 读 PSP 到 R0 |
| `MSR PSP, R0` | 写 R0 到 PSP |
| `LDR R3, =pxCurrentTCB` | R3 = 全局指针变量的地址 |
| `LDR R2, [R3]` | R2 = 当前 TCB 地址 |
| `STR R0, [R2]` | 旧 TCB 首成员 = 新保存栈顶 |
| `STMDB R0!, {...}` | 低地址开栈并保存寄存器 |
| `LDMIA R0!, {...}` | 从低地址读取寄存器并更新指针 |
| `TST R14,#0x10` | 判断是否有扩展浮点异常栈帧 |
| `MSR BASEPRI,R0` | 设置部分可配置异常的优先级屏蔽阈值 |
| `BL vTaskSwitchContext` | 选下一个 TCB（可能仍选旧任务） |
| `BX R14` | 在异常中按 EXC_RETURN 恢复并返回 |

## 五道自测题（先答再看答案）

1. `LDR R3,=pxCurrentTCB` 和 `LDR R1,[R3]` 分别得到什么？
2. 为什么 Task1 的局部变量 `count` 不需要在 TCB 中逐个登记？
3. 保存 9 个 32 位寄存器，R0 从 `0x20001000` 变成多少？R4 在什么地址？
4. 如果 `vTaskSwitchContext` 之后 `pxCurrentTCB` 没变，是不是 PendSV 出错？
5. `BX LR` 在普通函数里和 PendSV 里最大的区别是什么？

<details>
<summary>参考答案</summary>

1. R3 得到 `&pxCurrentTCB`，R1 得到 `pxCurrentTCB` 的值（TCB 地址）。
2. 寄存器值按编号保存、栈内容仍在独立内存中，且恢复 PC 保证后续指令仍按编译器的访问规则读取。
3. `0x20000FDC`；R4 位于 `0x20000FDC`。
4. 不一定；调度器可能继续选择当前任务。
5. 普通函数 LR 是返回地址；异常 Handler LR 可为 EXC_RETURN，触发由硬件恢复栈帧的异常返回。

</details>
